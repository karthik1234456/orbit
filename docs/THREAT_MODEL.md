# ORBIT Threat Model & Security Specification

This document details the security posture, asset classification, trust boundaries, threat mitigation matrix, and residual risks for the ORBIT local AI agent.

Every mitigation listed below is traced directly to concrete code files and automated test cases within this repository.

---

## 1. Assets

| Asset | Description | Impact of Compromise |
| :--- | :--- | :--- |
| **Workspace Files** | Files residing in `workspace/` (source code, notes, user data). | Unauthorized modification, deletion, data exfiltration, or corruption. |
| **Persistent Memory** | SQLite database (`data/memory.db`) containing user facts, preferences, and system memories. | Poisoning the agent's long-term behavior, leaking sensitive historical context. |
| **Gemini API Key** | Secret credential (`GEMINI_API_KEY`) used to authenticate with Google Generative AI APIs. | Financial cost via quota exhaustion, unauthorized external API usage. |
| **Audit Logs** | Append-only structured JSONL logs (`logs/audit.jsonl`, `logs/runs.jsonl`). | Tampering with audit trails, accidental disclosure of logged credentials or sensitive inputs. |
| **User Attention** | User confirmation dialogs, keyboard prompts, and decision bandwidth. | Attention fatigue leading to click-through approval of destructive actions (alert fatigue). |

---

## 2. Trust Boundaries

```
                 +---------------------------------------------------+
                 |                   USER INTERFACE                  |
                 |      Keyboard (CLI)  /  GUI Dialogs (Tkinter)     |
                 +---------------------------------------------------+
                                         |  Explicit User Confirmation
                                         v
+------------------------+      +------------------+      +------------------------+
|   EXTERNAL / UNTRUSTED |      |   ORBIT ENGINE   |      |      HOST SYSTEM       |
| Document Ingestion     | ---> | Agent Loop       | ---> | Workspace Filesystem   |
| Web Browser Targets    |      | Guards & Taint   |      | Whitelisted Apps       |
| Poisoned Prompts       |      | Audit Logger     |      | Desktop OS Shell       |
+------------------------+      +------------------+      +------------------------+
                                         ^
                                         |  Inference & Tool Calls
                                         v
                                +------------------+
                                |  CLOUD PROVIDER  |
                                |  Google Gemini   |
                                +------------------+
```

1. **User vs. LLM Output**: The model is considered non-deterministic and potentially susceptible to persuasion or hallucination. LLM requests to perform sensitive actions (file writes, app launches, URL opening) are gated by human-in-the-loop confirmation.
2. **LLM Output vs. Documents / External Content**: Documents loaded from disk or web pages are untrusted. Once an untrusted tool executes, the agent transitions to a "tainted" state, warning downstream reasoning steps.
3. **Orbit Engine vs. Local Machine**: The agent process executes with the privileges of the local Windows user, but its file tools are restricted strictly to `workspace/`, and executable launching is restricted to an allowlist.

## 4. Residual Risks

Despite the defensive layers implemented in ORBIT, several residual risks remain inherent to its architecture:

1. **Heuristic Injection Bypasses**: Heuristic pattern filters (`rag/safety.py`, `memory/safety.py`) match known prompt injection phrases. Sophisticated attackers can bypass regex patterns via adversarial token manipulation, multi-language encoding, or semantic indirection.
2. **Model Deception for Allowed Actions**: Even with taint warnings active, a compromised or confused LLM may still request an allowed tool call (such as writing to a critical workspace file or launching an allowed application) under pretexts that mislead the user.
3. **User Confirmation Responsibility**: The human-in-the-loop confirmation model relies on user scrutiny. If the user approves an action via `y` or the "Allow" button without verifying the arguments, ORBIT executes it faithfully within the bounds of the tool.
4. **Host Environment Vulnerability**: ORBIT operates as a native Python process under the host user's Windows security context. It does not run inside a Hyper-V microVM or OS AppContainer. If the host machine is already compromised by malware, malicious processes can inspect ORBIT's memory, manipulate SQLite databases directly, or read `.env` configuration files.
5. **Wrong or Outdated Passages in the Prompt**: Automatic document retrieval is conservative. It reliably catches questions whose words closely match the documents; chatty or paraphrased questions can be missed, in which case the model may still call the search tool itself. On a hard internal benchmark (16 questions, dev split) recall was 50% with 0 false injections on general questions; looser scoring methods reached 81-100% recall but inserted irrelevant passages into about a third of unrelated questions. Mitigations include outdated-document labels, withheld flagged passages, and taint warnings on risky actions.
6. **Browser Control Residual Risks**:
   - **Dynamic Site Selectors & Breakage**: Web layouts change over time. If external sites alter their HTML structure or CSS class names, selectors in `config/browser_sites.py` can break or return fewer results until selector configurations are updated.
   - **DNS Resolution to Private Addresses**: The URL guard performs lexical and IP-level analysis, but DNS names that resolve to private addresses are not caught upfront to avoid blocking public domains or failing in offline/split-horizon environments.
   - **Misleading Web Content & Ads**: A site's own page can still contain misleading content or video advertisements that delay playback or alter DOM interactions.
   - **User Confirmation Responsibility**: An approved action (e.g. opening a public website confirmed by the user) remains the user's responsibility.
7. **Command Chaining Residual Risks**:
   - **An Approved Plan Runs Several Actions**: When a user approves a plan preview, the approved sequence runs automatically across its steps until completion or until a step requires its own explicit approval.
   - **Misleading Page Titles**: While page text is redacted from diagnostics and plan summaries, page titles in the browser window can still mislead the user.
8. **Voice Input Residual Risks**:
   - **Misheard Commands Still Gated by Approval Flow**: A misrecognized voice command can request unintended actions, but any sensitive action (opening sites, running apps, writing files) is still gated by the standard confirmation dialog requiring manual user approval.
   - **Background Speech Transcribed While Mic Is Open**: If the microphone button is clicked and speech from television, coworkers, or background audio occurs, Whisper will transcribe that speech into the input prompt.
   - **Accidental Activation in Noisy Environments**: Ambient audio exceeding RMS thresholds may produce unintentional transcripts if recording is left active until the 30-second cap.
9. **Planted or Misleading Reminders Residual Risks**:
   - **Approved Misleading Wording**: An approved reminder can still contain deceptive or misleading wording if the user approves it without scrutinizing the text.
   - **Persisted Across Restarts**: A persisted reminder survives application restarts in `data/reminders.db`, firing or reporting as missed on subsequent startup.
10. **Tool Routing Optimization (Not a Security Boundary)**:
    - **Optimization, Not Authorization**: Tool routing (`TOOL_ROUTING=1`) is strictly a performance and precision optimization designed to reduce prompt token footprint and improve small local model compliance. It is **not** an authorization mechanism, sandbox, or security boundary.
    - **Permissions, Confirmations, and Audits Unchanged**: Routing does not alter tool permission levels (`SAFE`, `CONFIRM`, `DENY`), safety prechecks, human confirmation prompts, taint tracking, or audit logging.
    - **Off-Route Execution & Telemetry**: If the model hallucinates or intentionally generates a call to a registered tool that was not offered in the filtered subset ("off-route call"), the call is not blocked by routing. It executes through the standard agent dispatch pipeline with all usual permission checks and prechecks, and is tracked in telemetry (`run.off_route_call += 1`) and audit logging (`extra={"off_route_call": True}`).
11. **Environment Doctor Safety Principles**:
    - **Read-Only Guarantees**: The environment doctor (`core/doctor.py`, `scripts/doctor.py`) is strictly read-only. It inspects configuration, filesystem structure, and system services, but never executes remediation commands, never installs packages, never runs shell commands, and never alters files on disk.
    - **Strict Secret Redaction**: All environment variables and configuration settings are scrutinized. Any variable containing `KEY`, `TOKEN`, `SECRET`, or `PASSWORD` in its name is strictly reported as `"set"` or `"not set"`. Values, prefixes, suffixes, and character lengths are never output in reports, JSON streams, or diagnostics files.
    - **No Automatic Remediation**: Fixes are presented as plain-text recommendations for human review. ORBIT never automatically executes any proposed remediation action, preventing unreviewed configuration changes or unexpected package installations.
    - **Loopback Enforcement**: Network probing is strictly confined to loopback addresses (`127.0.0.1`, `localhost`). Non-loopback endpoints are never contacted unless `OLLAMA_ALLOW_REMOTE=true` is explicitly configured, protecting against internal network port scanning or unauthorized external HTTP requests.
12. **Persistent Action Sequences (Routines) Residual Risks**:
    - **An Approved Routine Runs Several Actions**: When a user approves a routine preview, the approved sequence executes automatically across its steps until completion or until a step requires its own explicit human approval.
    - **Routine Outliving Allowlist Changes**: A routine saved while an app or site was allowed could later become unsafe if the environment changes; ORBIT mitigates this by strictly re-validating the entire routine at run time against the current live allowlist before executing step 1.

13. **HUD Animation & Dock Cosmetic Boundaries**:
    - **Cosmetic Presentation Layer Only**: The HUD and bottom dock are cosmetic presentation layers only. They do not alter tool safety boundaries, permission levels, or confirmation logic. If canvas rendering fails, the system automatically falls back to classic panels.
14. **Demo Environment & Sample Data Isolation**:
    - **Separate Directory Sandbox**: Setting `ORBIT_HOME` isolates all databases, logs, and workspace files to a dedicated folder.
    - **Destructive Operation Safety**: Reset and seed commands strictly refuse to run against production roots, home directories, or drive roots, preventing accidental data erasure.

15. **Voice in Noisy Rooms & Acoustic Injection Defense**:
    - **Acoustic Injection Gating via Review Step**: Background speech from speakers, TV, or bystanders in noisy environments could be misrecognized as actionable commands. Under `VOICE_REVIEW="auto"`, low confidence (`avg_logprob < -1.0`), high unvoiced probability (`no_speech_prob > 0.6`), low signal-to-noise ratio (`SNR < 10 dB`), or single-word fragments (`words < 2`) gate auto-submission. The text is held in the input box with an explicit visual warning ("Low confidence" or "Noisy room: a headset helps"). It is never submitted to the agent loop until the user explicitly reviews and presses Enter (`source="voice-reviewed"`), or clears the box to cancel.
    - **Deterministic Alias Resolution**: Multi-token splits (e.g. "note pad", "you tube", "git hub") are checked strictly against allowlisted apps and sites. Aliases never guess: if zero or more than one candidate parses, the transcript is left unmodified.
    - **Physical Confirmation Boundaries Maintained**: Even when a voice command or alias successfully parses a shortcut action that requires confirmation (such as launching an app or opening an external site), confirmation dialogs (`ConfirmDialog`, `PlanDialog`) exclusively accept physical keyboard and mouse input. Spoken confirmation is strictly rejected.
    - **Evaluation Audio Stays Local**: Audio recordings recorded for benchmark evaluation (`scripts/voice_record.py`) are saved locally to `data/voice_eval/`, which is permanently git-ignored and blocked from remote transmission or demo mode usage.
